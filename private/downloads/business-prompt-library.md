# The Business Prompt Library

**TIBLOGICS** · 60 prompts that hold up on real work.

Every prompt here follows the same structure: **task, context, audience,
constraints.** That is not a style preference — it is the difference between
a usable draft and generic filler.

Replace `[BRACKETED]` text. Paste the actual material rather than describing
it; models work far better with the real thing in front of them.

---

## How to use this

1. **Paste the real material.** Not a summary of it.
2. **Push back at least twice.** The first output is a starting point.
3. **Check anything with a number, date, name or citation in it.**

A note on the prompts that ask for criticism: their value is that the model
has no ego invested in your work. Use them before the meeting, not after.

## 1. Writing & editing

**1.1 — Edit, don't ghostwrite**
```
Here is my draft. Improve the clarity and flow without changing my voice or
adding claims I haven't made. Keep my sentence rhythm. Point out anything
that reads as padding.

[PASTE DRAFT]
```

**1.2 — Diagnose, don't rewrite**
```
Read this and tell me what is unclear. Do NOT rewrite it. List the specific
sentences a reader would stumble on and say why.

[PASTE DRAFT]
```

**1.3 — Cut ruthlessly**
```
Cut this by 30% without losing any substantive point. Show me what you cut
and why, so I can disagree.

[PASTE DRAFT]
```

**1.4 — Is the ask obvious?**
```
A busy person will read this for 8 seconds. Tell me what they will think the
ask is. If that is not "[YOUR ACTUAL ASK]", tell me where it goes wrong.

[PASTE DRAFT]
```

**1.5 — Match a house style**
```
Here are two things we have published. Rewrite the third to match their
tone, sentence length and formality.

EXAMPLE 1: [PASTE]
EXAMPLE 2: [PASTE]
REWRITE THIS: [PASTE]
```

**1.6 — Difficult message**
```
Write a message to [WHO] about [SITUATION]. I need to [GOAL] without
[WHAT TO AVOID]. Our relationship is [CONTEXT]. Under [N] words. Direct, not
cold. No corporate euphemism.
```

**1.7 — Reply to a complaint**
```
Draft a reply to this complaint. Both facts in it are true. Acknowledge
genuinely without admitting liability. I want them to come back. Under 150
words, plain language, no defensiveness.

[PASTE COMPLAINT]
```

## 2. Summarising & extraction

**2.1 — Decisions, not summary**
```
Read this and list only the decisions I need to make, and by when. Ignore
background.

[PASTE]
```

**2.2 — What's missing**
```
Read this [CONTRACT/PROPOSAL/PLAN]. What is NOT addressed that should be?
Absence is what I am asking about, not a summary of what's there.

[PASTE]
```

**2.3 — Extract to a table**
```
Extract every [action item / figure / deadline / commitment] from this into a
table with columns: [COLUMNS]. If something is ambiguous, put it in a
separate "unclear" list rather than guessing.

[PASTE]
```

**2.4 — The strongest counter-argument**
```
Summarise the strongest argument AGAINST the position taken here. Steelman
it — I want the best version, not a strawman.

[PASTE]
```

**2.5 — Thread to brief**
```
Condense this email thread into: (1) what was decided, (2) what is
outstanding, (3) who owes what to whom. Note any point where two people
appear to think different things were agreed.

[PASTE THREAD]
```

## 3. Thinking & planning

**3.1 — Argue against me**
```
Here is my plan. Argue against it as strongly as you can. Assume you are the
most sceptical person in the room and you have seen this fail before.

[PASTE PLAN]
```

**3.2 — What am I not considering?**
```
[DESCRIBE SITUATION AND PLAN]

What am I not considering? Focus on second-order effects and on who this
affects that I have not mentioned.
```

**3.3 — Pre-mortem**
```
It is [SIX MONTHS] from now and this failed badly. Write the post-mortem.
What were the three most likely causes?

[PASTE PLAN]
```

**3.4 — Break into steps**
```
Break this into steps with dependencies. Flag which assumptions are load-
bearing — the ones where being wrong invalidates the rest.

[DESCRIBE GOAL]
```

**3.5 — Decision brief**
```
Turn this into a one-page decision brief for [WHO]: the decision, the
options, the trade-off for each, and a recommendation with its main risk.

[PASTE CONTEXT]
```

**3.6 — Questions I should be asking**
```
I am about to [DECISION/MEETING/PURCHASE]. What questions should I be asking
that someone inexperienced in this would not think to ask?
```

## 4. Customer & sales

**4.1 — Objection handling**
```
A prospect said: "[OBJECTION]". Context: [WHAT WE SELL, PRICE POINT, WHO
THEY ARE]. Give me three responses at different levels of directness. Do not
be pushy — if the objection is legitimate, say so.
```

**4.2 — Proposal from notes**
```
Turn these notes into a proposal for [CLIENT]. Structure: their problem in
their words, what we'd do, what they get, timeline, price. Lead with their
problem, not our credentials.

[PASTE NOTES]
```

**4.3 — Follow-up that isn't annoying**
```
Write a follow-up to [WHO], [N] days after [WHAT HAPPENED]. Give them a
reason to reply that is useful to them. Under 80 words. No "just checking
in", no false urgency.
```

**4.4 — Tighten a case study**
```
Rewrite this case study to lead with the client's result rather than our
process. Keep every number. Cut anything that is about us rather than them.

[PASTE]
```

## 5. Operations & internal

**5.1 — Write the SOP**
```
Turn this into a procedure a new starter could follow unaided. Number the
steps. Flag every point where judgement is required rather than a rule.

[DESCRIBE PROCESS]
```

**5.2 — Meeting to actions**
```
From these notes, produce: decisions made, actions with an owner and a date,
and open questions. If an action has no clear owner, list it as unassigned
rather than guessing.

[PASTE NOTES]
```

**5.3 — Job description**
```
Write a job description for [ROLE]. Describe what the person will actually
do in week one and month three. Avoid "rockstar", "ninja", "fast-paced
environment" and anything else that says nothing.
```

**5.4 — Explain upward**
```
Explain [TECHNICAL THING] to [ROLE] who cares about [THEIR CONCERN]. No
jargon. Lead with what it means for them. Under 150 words.
```

**5.5 — Process audit**
```
Here is how we currently do [PROCESS]. Where is the wasted effort? Where
would an error most likely go unnoticed?

[DESCRIBE PROCESS]
```

## 6. Learning

**6.1 — Explain at three levels**
```
Explain [TOPIC] three times: to a ten-year-old, to a smart adult outside the
field, and to a practitioner. I want to see where the simplifications break.
```

**6.2 — Test me**
```
I have just read about [TOPIC]. Ask me six questions to check whether I
actually understood it. Tell me where I am wrong, and why — do not be
generous.
```

**6.3 — Common misconceptions**
```
What do people usually get wrong about [TOPIC]? Include the ones that sound
right.
```

## 7. Verification

Use these on output before you rely on it.

**7.1 — Separate fact from inference**
```
Go back through your last answer. Mark each claim as: (a) something you are
confident is established fact, (b) an inference you drew, (c) something you
are unsure about. Be honest about (c).
```

**7.2 — What would change your answer?**
```
What information, if I gave it to you, would most change the answer you just
gave?
```

**7.3 — Evidence check**
```
What is the evidence for the specific claim that [CLAIM]? If you are not
confident it is established, say so plainly rather than justifying it.
```

> **Do not use "are you sure?"** These systems are trained to be agreeable
> and will often abandon a correct answer under pressure. Ask for the
> evidence instead — that tests the claim rather than the model's willingness
> to please you.
